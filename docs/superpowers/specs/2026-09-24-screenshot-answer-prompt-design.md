# 截图回答提示词设计

## 目标

调整截图问答的视觉系统提示词，使模型在面试场景下只返回可直接使用的答案或代码，并能根据截图内容区分编程题与问答题。

## 范围

- 修改 `electron/llm/prompts.ts` 中 `buildVisionMessages` 生成的系统提示词。
- 保留现有截图调用链、视觉模型调用方式、流式输出方式和参考资料拼接逻辑。
- 不修改普通文本问答、转录上下文、历史问答或 UI。

## 行为设计

### 1. 内部分类

模型先在内部判断截图属于编程题还是问答题，不把分类过程、推理过程或客套话输出给用户。

### 2. 编程题

- 根据题面、代码模板和输入输出描述判断 ACM 或牛客格式。
- ACM 格式输出可直接提交的完整程序。
- 牛客格式只输出截图要求的函数或类实现，不自行补充完整 `main` 模板。
- 语言只在 C++ 和 Python 中选择：算法题使用 C++，Agent 相关实现题使用 Python。
- 输出只包含代码块；关键步骤用凝练注释说明，时间复杂度和空间复杂度写在代码注释中。
- 不输出代码块之外的解释、分析或前缀。

### 3. 问答题

- 输出可以直接用于面试回答的简洁答案。
- 选择题只输出正确选项或选项内容。
- 不输出分类结果、长篇推理、客套话或“答案如下”等前缀。

### 4. 参考资料

- 继续保留第二简历优先于简历的规则。
- 不得把参考资料中的示例说成用户本人经历。
- 与截图题目无关的参考资料不应改变编程题答案。

## 实现方案

采用单个视觉系统提示词明确描述决策顺序和输出约束。相比增加一次分类请求或增加 UI 手动模式，该方案不增加请求次数、延迟和交互步骤，且兼容当前视觉模型的流式回答。

## 数据流与错误处理

截图和用户问题仍作为同一个多模态用户消息发送。用户问题为空时，提示词要求模型直接按上述规则处理截图内容。模型无法可靠判断平台时，应根据截图中的函数签名、输入输出模板和提交格式选择最接近的形式，并继续给出答案，不输出判断过程。

## 验证标准

- `buildVisionMessages` 的系统消息包含上述分类、语言、平台和输出约束。
- 现有简历参考资料仍被拼接到系统消息中。
- 截图用户消息结构和默认问题文本保持兼容。
- 只产生目标提示词文件的后续实现差异，不改动无关文件。
